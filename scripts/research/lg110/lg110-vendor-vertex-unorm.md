# LG110 UNORM vertex formats: metadata and single-B causal mutation

Date: 2026-11-10

## Scope

This extends [`lg110-vendor-vertex-format.md`](lg110-vendor-vertex-format.md)
from four 32-bit float formats to four normalized integer UV formats.  The
installed vendor file remains `/usr/lib/gsgpu/dri/gsgpu_dri.so`, SHA-256
`aff7101ab877db0026fa0f8274e03a579f1b4fd2c16fabe2478d08f224d0da0a`.
No installed driver, kernel module, or vkgl library was modified.  GDB writes
were limited to descriptors in the short-lived test process.

This is descriptor research, not a native Vulkan implementation or performance
claim.  The harness still has its previously documented swapchain semaphore
validation issue; these runs are not claimed to be validation-clean.

## Raw metadata and final descriptors

Each read-only GDB run captured 11 UV constructions.  Every entry retained
words 0/1/2 = `0x022c4000`, `0x00100001`, `0x00000040` and satisfied:

```
word3[18:0] = raw_metadata[50:32]
```

| Vulkan UV format | Raw 64-bit metadata | Final word 3 |
| --- | ---: | ---: |
| R8G8_UNORM | `0x0001822c00000000` | `0x0001822c` |
| R8G8B8A8_UNORM | `0x00050fac00000000` | `0x00050fac` |
| R16G16_UNORM | `0x0002822c00000000` | `0x0002822c` |
| R16G16B16A16_UNORM | `0x00077fac00000000` | `0x00077fac` |

RGBA16 has the same observed word 3 as the previously measured RGBA32 float
format.  This is an observation for this vendor path, not a claim that the two
formats are generally interchangeable.

## Native A/B/A pixel controls

The first and third pipelines remain R32G32_SFLOAT; only the second UV format
changes.  All four native runs passed their exact pattern assertions:

| Second format | A / B / A pixel bytes | Pattern |
| --- | --- | --- |
| R8G8_UNORM | `007010ff / 000000ff / 007010ff` | distinct B |
| R8G8B8A8_UNORM | `007010ff / 000000ff / 007010ff` | distinct B |
| R16G16_UNORM | `007010ff / 001000ff / 007010ff` | distinct B |
| R16G16B16A16_UNORM | `007010ff / 007010ff / 007010ff` | same-colour control |

The input allocation deliberately remains unchanged.  Consequently these are
format-routing and causal-descriptor tests, **not** numeric UNORM conversion
conformance tests.  In particular, RGBA16 is not reported as causally distinct
when this input produces the same colour as A.

## Single-B causal restoration

`gsgpu-mutate-vertex-format-pair.gdb` receives source and destination word 3
values with GDB `-ex` options.  At the three submitted UV BO offsets it permits
A = `0x0005f22c`, mutates only the matching B descriptor, and counts every
unexpected old value.  For each of the three distinct UNORM formats:

```
B source -> 0x0005f22c (R32G32_SFLOAT)
MUTATIONS=1 UNEXPECTED=0
```

The sole write was at BO offset `0x8f90`.  In all three runs the B pixel then
became exactly `007010ff`, producing byte-identical A/A/A pixels and passing the
harness's explicit `LG110_EXPECT_FORMAT_MUTATION=1` assertion.  Thus the new
word 3 values are not merely correlated with construction: changing only B's
format field removes B's measured pixel difference.

RGBA16 remains metadata-only because its native B pixel already equals A; no
pixel causality is claimed for that variant.
